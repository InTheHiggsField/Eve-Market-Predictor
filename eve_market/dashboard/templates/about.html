About the predictions

How the data is collected, what the models do, how they're evaluated, and how to reproduce everything on your own machine.

What gets tracked

Only two hand-picked lists are collected, both defined in data_sets/tracked_items.py as {"in-game name": type_id} dictionaries:

  • Core (TRACKED_ITEMS, {{ n_core }} items): PLEX, skill injectors and extractors, Logic Circuits, and the most-traded Marauders and pirate cruisers. These are the highest-value, highest-turnover items in the game.
  • Commodities (COMMODITY_ITEMS, {{ n_commod }} items): all fifteen minerals, the most-traded compressed ores, and T2 and capital ship components.

Items were chosen by average ISK traded per day over 90 days, keeping items that also have enough individual trades per day for prices to be meaningful. The seven specialty minerals are the exception: they're included for completeness but trade only a handful of times a day, so their forecasts are very noisy.

Trade hubs

The same items are tracked at the five major high-sec trade hubs and at Zarzakh, CCP's neutral null-sec hub, all defined in data_sets/markets.py. Use the Market picker at the top of the Market data and Predictions pages to switch between them.

ESI only keeps price history per region, so a hub's charts and forecasts reflect every trade in its region; most of that volume happens at the hub station itself. Order-book snapshots are filtered to the hub station. PLEX trades on one global market, so its price history is the same at every hub, but its bid/ask is still taken at each hub's station. Each hub gets its own model, trained only on that hub's history.

Other low-sec and null-sec trading mostly happens in player citadels with private markets, which ESI only shows to characters allowed to dock there. Zarzakh is alone in its region, so its history really is the hub's own, but it is a thin market (24 of the tracked items trade there, since November 2023).

Where the data comes from

Everything comes from EVE's public ESI API; no login is needed.

EndpointWhat we keep
/markets/{region}/historyOne row per item per day: average, highest and lowest trade price, units traded, number of trades. ESI serves about 13 months.
EVE Ref archiveOlder daily history in the same format, archived from ESI back to 2003-10-01. backfill streams each day's file, keeps only the tracked items, and stores them; nothing else is saved to disk.
/markets/{region}/ordersA snapshot of the live order book each time you collect: best bid, best ask, and total volume on each side at each hub station.

Items are fetched from each hub's region. PLEX is the exception: it moved to its own global market (region {{ region_overrides['PLEX'] }}), so current data is fetched from there and its order snapshot covers the whole market rather than one station. Its older Jita history is kept too; if both markets have a row for the same day, the one with more volume is used. Items only have history from their release (for example, today's PLEX and skill injectors date from 2016–2017).

Data is stored in a local SQLite file, data/market.db. Collecting again updates history in place and appends a new order snapshot, so running it daily builds a bid/ask history that ESI doesn't keep for you.

Station prices

Players trade at a specific station, not "in a region", so the hub station's own price is what matters. ESI has no per-station history, so the tool builds one: a Windows scheduled task (EVE Market Collect) runs every hour and saves each hub station's order book.

  • Station mid is halfway between the best 5% of buy volume and the best 5% of sell volume at the station, ignoring orders more than 20% from the best price. That's steadier than the single best order, which can be one bait unit or a huge lowball buy order.
  • Premium is how far the station mid sits from the region's daily average. It's small in Jita (about 3%), where the station does nearly all the region's trading, and larger at the smaller hubs (up to about 11% in Rens).
  • Station forecast: until there are {{ min_station_days }} days of hourly snapshots, the regional forecast's percentage move is applied to the current station mid. After that, a station model takes over. It uses the regional features above plus the station premium, the station's own 1/3/7-day returns and its spread, and predicts the station mid directly. The Predictions page says which one is in use.

What the model predicts

For each item and day t, the target is the log return of the daily average price over the next h days: log(price[t+h] / price[t]), with h = 7 by default. A log return of 0.05 is roughly a 5% rise. Days with no trades carry the last price forward with zero volume.

Each day is described by these features, all computed only from data up to that day:

One model is trained across all items in a list at once (a "pooled" model). That gives it far more examples than any single item has, at the cost of assuming items behave similarly once their features are scaled.

How the models are evaluated

A walk-forward backtest mimics using the model in real time. The last 105 days are split into five 21-day test windows. For each window the model is trained only on data that ended h days before the window starts (so no training target overlaps the test period), then scored on that window.

  • MAE: average absolute error of the predicted log return. Lower is better; compare it against "no change".
  • Direction: how often the model got the sign of the move right, on days the price actually moved. 50% is a coin flip.

The orange dots on each prediction chart are those out-of-sample backtest predictions, plotted on the date they were aiming at, so you can see how the model has tracked reality.

Limitations

  • On the core list (PLEX, injectors, ships) the models currently do not beat "no change". These markets are deep and efficient, and the features above don't capture what moves them (patch notes, PLEX sales, events).
  • On liquid commodities, Ridge beats the baseline modestly (about 4% lower error, ~60% direction accuracy).
  • The daily average mixes buy-order and sell-order fills, so part of any day-to-day "move" is just which side traded more. That flatters direction accuracy.
  • The backtest ignores broker fees, sales tax, and how much you could actually trade without moving the price.
  • Markets from a decade ago behaved differently (fewer players, different game mechanics), so old history adds examples but not always relevant ones.

Nothing here is financial advice, in-game or otherwise.

How to replicate

On Windows, from the repository folder:

py -3.13 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python -m eve_market collect                    # both lists, ~30 seconds
python -m eve_market backfill                   # one-off: history back to 2003 (several GB streamed; re-run to resume)
python -m eve_market backtest --list commodities --market Amarr
python -m eve_market forecast --list core --model ridge --out data/forecast.csv
python -m eve_market dashboard                  # this site, at http://127.0.0.1:5000
python -m eve_market backtest --station --market Jita   # station model, once enough snapshots exist

On Windows, run these through the included eve wrapper (.\eve collect) or after activating the venv. The hourly task runs scheduled_collect.pyw, which takes snapshots every hour and refreshes daily history every 12 hours; its log is data/collect.log. Remove it with Unregister-ScheduledTask -TaskName "EVE Market Collect".

Options: --market Jita|Amarr|Dodixie|Hek|Rens|Zarzakh (collect and backfill take several, default all), --list core|commodities|all, --horizon N, --model ridge|gbm, and for the dashboard --port. To keep data current, schedule python -m eve_market collect once a day (ESI history updates shortly after downtime, 11:00 UTC). Refresh this page after collecting; predictions retrain automatically when new data arrives.

To track a different item, add its name and type_id to one of the dictionaries in data_sets/tracked_items.py (and a display group in ITEM_GROUPS), then collect again. Type IDs can be looked up in data_sets/invTypes_clean.csv.
