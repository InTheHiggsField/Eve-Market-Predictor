About the predictions

How the data is collected, what the models do, how they're evaluated, and how to reproduce everything on your own machine.

What gets tracked

Only two hand-picked lists are collected, both defined in data_sets/tracked_items.py as {"in-game name": type_id} dictionaries:

  • Core (TRACKED_ITEMS, {{ n_core }} items): PLEX, skill injectors and extractors, Logic Circuits, and the most-traded Marauders and pirate cruisers. These are the highest-value, highest-turnover items in the game.
  • Commodities (COMMODITY_ITEMS, {{ n_commod }} items): all fifteen minerals, the most-traded compressed ores, and T2 and capital ship components.

Items were chosen by average ISK traded per day over 90 days, keeping items that also have enough individual trades per day for prices to be meaningful. The seven specialty minerals are the exception: they're included for completeness but trade only a handful of times a day, so their forecasts are very noisy.

Where the data comes from

Everything comes from EVE's public ESI API; no login is needed.

EndpointWhat we keep
/markets/{region}/historyOne row per item per day: average, highest and lowest trade price, units traded, number of trades. ESI serves about 13 months.
/markets/{region}/ordersA snapshot of the live order book each time you collect: best bid, best ask, and total volume on each side at Jita 4-4.

Items trade in The Forge (Jita). PLEX is the exception: it moved to its own global market (region {{ region_overrides['PLEX'] }}), so it is fetched from there and its order snapshot covers the whole market rather than one station.

Data is stored in a local SQLite file, data/market.db. Collecting again updates history in place and appends a new order snapshot, so running it daily builds a bid/ask history that ESI doesn't keep for you.

What the model predicts

For each item and day t, the target is the log return of the daily average price over the next h days: log(price[t+h] / price[t]), with h = 7 by default. A log return of 0.05 is roughly a 5% rise. Days with no trades carry the last price forward with zero volume.

Each day is described by these features, all computed only from data up to that day:

FeatureMeaning
ret_1 … ret_30Log return over the past 1, 3, 7, 14 and 30 days
vol_7, vol_30Standard deviation of daily returns over 7 and 30 days (volatility)
ma_ratio_7, ma_ratio_30How far today's price sits above or below its 7- and 30-day moving average
range_pctToday's high minus low, as a fraction of the average price
volume_zToday's volume compared with its 30-day norm (z-score of log volume)
dowDay of the week (weekend activity differs)

One model is trained across all items in a list at once (a "pooled" model). That gives it far more examples than any single item has, at the cost of assuming items behave similarly once their features are scaled.

Models

ModelWhat it does
No change (baseline)Always predicts a 0% move. Any useful model must beat this.
Momentum (baseline)Predicts the last h days' move will repeat.
Ridge regressionA linear model on standardized features with L2 regularization (alpha=10). Simple and hard to overfit; currently the most reliable.
Gradient boostingscikit-learn's HistGradientBoostingRegressor (300 trees, learning rate 0.05, 15 leaves, min 50 samples per leaf). Can capture non-linear effects but needs more data to pay off.

The shaded forecast range on the Predictions page is ±1 standard deviation of the expected h-day move, estimated as the item's 30-day volatility × √h. It's a rough guide to typical noise, not a guaranteed interval.

How the models are evaluated

A walk-forward backtest mimics using the model in real time. The last 105 days are split into five 21-day test windows. For each window the model is trained only on data that ended h days before the window starts (so no training target overlaps the test period), then scored on that window.

  • MAE: average absolute error of the predicted log return. Lower is better; compare it against "no change".
  • Direction: how often the model got the sign of the move right, on days the price actually moved. 50% is a coin flip.

The orange dots on each prediction chart are those out-of-sample backtest predictions, plotted on the date they were aiming at, so you can see how the model has tracked reality.

Limitations

  • On the core list (PLEX, injectors, ships) the models currently do not beat "no change". These markets are deep and efficient, and the features above don't capture what moves them (patch notes, PLEX sales, events).
  • On liquid commodities, Ridge beats the baseline modestly (about 4% lower error, ~60% direction accuracy).
  • The daily average mixes buy-order and sell-order fills, so part of any day-to-day "move" is just which side traded more. That flatters direction accuracy.
  • The backtest ignores broker fees, sales tax, and how much you could actually trade without moving the price.
  • Thirteen months of history is short; seasonal effects can't be learned yet.

Nothing here is financial advice, in-game or otherwise.

How to replicate

On Windows, from the repository folder:

py -3.13 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python -m eve_market collect                    # both lists, ~30 seconds
python -m eve_market backtest --list commodities
python -m eve_market forecast --list core --model ridge --out data/forecast.csv
python -m eve_market dashboard                  # this site, at http://127.0.0.1:5000

Options: --list core|commodities|all, --horizon N, --model ridge|gbm, and for the dashboard --port. To keep data current, schedule python -m eve_market collect once a day (ESI history updates shortly after downtime, 11:00 UTC). Refresh this page after collecting; predictions retrain automatically when new data arrives.

To track a different item, add its name and type_id to one of the dictionaries in data_sets/tracked_items.py (and a display group in ITEM_GROUPS), then collect again. Type IDs can be looked up in data_sets/invTypes_clean.csv.
